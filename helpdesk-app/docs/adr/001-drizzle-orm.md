# ADR-001: Drizzle ORM for data access and migrations

**Status:** Accepted · **Date:** 2026-09-30

## Context
We need PostgreSQL access with parameterized queries, versioned migrations that run safely in CI/CD,
and small container images for a budget Azure deployment. The team is new to Azure.

## Options considered
| | Drizzle | Prisma |
|---|---|---|
| Complexity | Low: schema is plain JS | Medium: separate schema DSL + generate step |
| Runtime footprint | Pure JS | Query-engine binary per platform |
| Migrations | Plain `.sql` files, easy to review | SQL files, managed by Prisma CLI |
| SQL control | High: query builder close to SQL | Lower: abstracted client |

## Decision
Use **Drizzle** (`drizzle-orm` + `pg`). Migrations are generated by `drizzle-kit` (dev dependency only)
and applied in production by `src/db/migrate.js`, which uses `drizzle-orm/migrator` under a Postgres advisory lock.

## Consequences
- ✅ Every query is parameterized by construction. The migration SQL can be reviewed in PRs.
- ✅ No engine binaries, so Alpine images stay small and builds download less.
- ⚠️ Hand edits to generated SQL (e.g. `CREATE EXTENSION pg_trgm`) must be kept in sync with the snapshot.
- ⚠️ Fewer high-level features than Prisma (no built-in soft delete or middleware).
